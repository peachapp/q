# 大文件上传

## 背景：

做 AI 产品方面的，会涉及到用户自定义**模型**（1G 以上）。

经常遇到一些问题：

- 网络断开之后，之前传的没了
- 传着传着，网络波动了，结果啥都没了
- 关机了，想接着传，做不到

专业术语：

- 断点续传
- 断开重重连传
- 切片上传

## 解决方案：

- 前端切片。chunk 1024M（1048576K），每个切片 500K， `const size = 1048576 / 500`。
- 将切片传递给后端，切片要取名：hash、index。
- 后端组合切片。

### 加料：

- 前端切片：主线程做切片会卡顿，webworker 多线程切片，处理完后交给主进程发送。
- 切完后，将 blob 存储到 IndexedDB，下次用户进来之后，嗅探一下是否存在未完成上传到切片，有就尝试继续上传。
- websocket，实时通知，和请求序列的控制 wss。
- 整体说一说这个大文件上传器整体设计
  - 组件设计
  - props、事件、状态
  - 拖拽上传、多文件选择
  - 通用化不同文件的上传，上传统一协议

### 落地：

```html
<input type="file" id="fileInput" />
<button onclick="uploadFile()">Upload</button>

<script>
  const CHUNK_SIZE = 5 * 1024 * 1024; // 每个切片大小为5MB
  function uploadFile() {
    const file = document.getElementById("fileInput").files[0];
    if (!file) {
      alert("Please select a file.");
      return;
    }

    const totalChunks = Math.ceil(file.size / CHUNK_SIZE);
    let currentChunk = 0;

    function uploadChunk() {
      if (currentChunk >= totalChunks) {
        console.log("Upload complete");
        return;
      }
      const start = currentChunk * CHUNK_SIZE;
      const end = Math.min(start + CHUNK_SIZE, file.size);
      const chunk = file.slice(start, end);

      const formData = new FormData();
      formData.append("file", chunk);
      formData.append("chunkNumber", currentChunk + 1);
      formData.append("totalChunks", totalChunks);

      fetch("/upload", {
        method: "POST",
        body: formData,
      })
        .then((response) => {
          if (response.ok) {
            currentChunk++;
            uploadChunk(); // 递归调用上传下一块
          } else {
            console.error("Chunk upload failed");
          }
        })
        .catch((error) => {
          console.error("Upload error", error);
        });
    }
    uploadChunk();
  }
</script>
```

### 反思和优化：

缓存和实时通知。
